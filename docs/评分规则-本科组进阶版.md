# 厂仓物流协同运输场景 · 评分规则（本科组 · 进阶版）

## 赛题目标与车辆功能

### 赛题目标

在厂仓物流（厂区仓库物流）协同运输场景中，选手编写自动驾驶算法控制多车协同完成物资交付，具体任务如下：
1. 按 A → B → C 顺序确认现场信号，获取停车坪和编号车位信息；
2. 确认信号 C 后，由信号车或运输车在任务公布的扫码点 10 米内调用 `scan`，获取封闭道路信息并重新规划路径；
3. 运输车先后通过受控环岛；
4. 通过必经点 O，此项从开局即可触发；
5. 分别驶抵 A、B 泊位的指定车位停稳交付。
泊位的精确位置按信号确认进度公开；每车至多交付一个泊位，未完成全部任务时，已完成项按规则计分。

### 车辆功能

任务车辆共 **5 辆**：**2 辆运输车**（卡车）与 **3 辆信号车**（轿车）。

| 车辆 | 数量 / 车型 | 功能与权限 |
|---|---|---|
| **运输车** | 2 辆 / 卡车 | 可确认信号、扫码、触发必经点、申请通过受控环岛，并在指定车位停稳交付。每车至多交付一个泊位 |
| **信号车** | 3 辆 / 轿车 | 可确认信号、在三个信号齐备后按任务公布的位置扫码、触发必经点；环岛任务通行和泊位交付由运输车完成 |

权限要点：

- **验证码（A / B / C）**：对运输车与信号车**同时开放**，任一车辆驶入7 m 范围并调用 `submit_key` 提交正确验证码即计分，不要求同一辆车完成全部信号。
- **目标观测**：A 确认后公布停车坪 1，B 确认后公布停车坪 2，C 确认后公布两个编号车位和扫码点的具体位置。
- **必经点**：不限车型，运输车或信号车中心进入 3 m 范围并保持 0.5 s 即触发（本科组为计分项，专科组为必过门槛）。
- **其他交通参与者**：SUV、巴士、两轮车与行人仅作场景布景或动态障碍，不承担赛题任务。

### 1.3 动态障碍物清单（节选）

动态障碍物指**带直线运动预设**的车辆（`props.move = true`，沿车头方向以 `moveSpeed` 前进 `moveDistance` 米后停驻）。它们与静态窄口叠加，形成「通过时机窗口」—— 程序必须先预测动态车的位置与到达时间，再决定加速抢行、减速跟随还是停车等待。

**算法要求的变化**

| 能力 | v4（纯静态） | v5（含动态） |
|---|---|---|
| 障碍物表示 | 静态栅格 / ESDF | 需**时空占用预测**（按 moveSpeed 与剩余行程推算） |
| 决策 | 避障 → 通过 | **通行权博弈**：抢行 / 跟随 / 等待的代价比较 |
| 重规划触发 | 静态阻塞时 | 动态目标进入本车走廊且 TTC 低于阈值时 |
| 窄口处理 | 几何收窄 | 几何收窄 + **时间窗对齐**（等动态车让开再进） |

### 1.4 强制绕行：y = 1000 东段封闭

- 封闭区间：`x ∈ [2980, 3820]`，整幅封闭。扫码点设在封闭区外，具体位置在确认信号 C 后由任务公布。
- 检测边界：以该路段中心线两侧各 **7 m** 为界，检测带宽 **14 m**。
- 绕行通路（任选其一，均为已建成道路）：
  - `临港南北向道路`：`(2800,1000) → (2800,1960) → (4000,1960) → (4000,1000)`
- 也可反向绕行，按实际路况选路。
- 该封闭为**静态封闭**（不依赖扫描结果）：即使尚未完成路障扫描，运输车进入封闭区也会归零

> **加分项（时间附加分）**：全部任务完成时，用时每比基准 **300 s** 少 **1 秒**加 **2 分**，封顶 **+300 分**。按两位小数结算，见 §3。

> **必经点 `el_mwrj5xwvo1lrw`** 位于 `(4000, 1000)`，即临港南北向道路与 y=1000 行东段的交口，正好落在 y=1000 东段封闭区（`x ∈ [2980, 3820]`）的**外侧绕行转角**上。开局即可触发，漏过时仍可超时结算已完成项。该点为场景内既有元素（`obstacle / beacon`），**不参与碰撞判定**，仅作判定标靶。

### 2.3 定位精度与观测

泊位信息由信号确认进度逐步公开：

- A 确认后公布停车坪 1 的中心位置，B 确认后公布停车坪 2 的中心位置。
- C 确认后公布两个编号车位的具体位置和扫码点。
- 共享信息随任务状态更新，无需另行提交目标观测。
- **信标验证码（A / B / C）对运输车与信号车同时开放**：任一车辆驶入信号点7 m 范围并调用 `submit_key` 提交正确验证码即计分，不要求三个信号由同一辆车完成（例如运输车提交 A、信号车提交 B、C 同样有效）
- 信号车或运输车均可扫码。正式环岛通行和泊位交付仅限运输车。
- 到达必经点**不限车型**，运输车或信号车触发均计 300 分，但每局只能计一次

## 3. 时间附加分（v3 改版）

### 3.1 基准时间 T₀ = 300 s

本版直接指定 **T₀ = 300 s**。

参考线路（路网里程随实际选路变化）：

| 线路 | 里程 |
|---|---|
| 信号车：起点 → A 号信号 | 按实际选路 |
| 信号车：A → B 号信号 | 按实际选路 |
| 信号车：B → C 号信号 | 按实际选路 |
| 信号车：C → 任务公布的扫码点（含封路绕行） | 按实际选路 |
| **信号车线路合计** | 按实际路线合计 |
| 运输车 A：起点 → 受控环岛 | 按实际选路 |
| 运输车 A：受控环岛 → A 泊位 | 按实际选路 |
| **运输车 A 线路合计** | 按实际路线合计 |
| 运输车 B：起点 → 受控环岛 | 按实际选路 |
| 运输车 B：受控环岛 → B 泊位 | 按实际选路 |
| **运输车 B 线路合计** | 按实际路线合计 |

任务可由多车并行完成，实际用时取决于各车路线、等待和作业。

`T_op`（作业与等待）参考构成，沿用 v2 口径，仅作校核：

| 作业环节 | 时间 |
|---|---|
| 3 次信号读取与验证码提交 | 3 × 8 = 24 s |
| 扫码点扫描（驶近 10 m + 扫码） | 10 s |
| 2 次泊位停稳与交付确认 | 2 × 10 = 20 s |
| 中央路口互斥等待（两车依次通行） | 21 s |
| **合计** | **75 s** |

**150 s 及以内**完成全部任务可拿满时间分。达到 **300 s** 时，时间附加分为 0。

### 3.2 计分公式

```
ΔT  = T₀ − T_actual            （单位：秒；正值 = 快于基准）
S_t = round(clamp(2 × ΔT, 0, +300), 2)
```

| 参数 | 取值 | 含义 |
|---|---|---|
| `T₀` | **300 s** | 基准时间（直接指定） |
| `k` | **2 分 / 秒** | 每比基准快 1 秒加 2 分 |
| `S_max` | **+300 分** | 加分封顶 |
| 下限 | **0 分** | 慢于 300 s 不加分，也不扣分 |

仅在全部任务完成且未触发归零时计算，并四舍五入保留两位小数。**实际用时每比基准少 1 秒加 2 分；慢于基准的秒数不计分（记 0），不产生负分。** 时间分只奖不罚，最大影响 +300 分（占任务分 1300 的 23%）。

### 3.3 算例

| 完成用时 T | ΔT = 300 − T | S_t | 说明 |
|---|---|---|---|
| 150 s | +150 | **+300.00（封顶）** | 时间分封顶 |
| 200 s | +100 | **+200.00** | 按公式计分 |
| 250 s | +50 | **+100.00** | 按公式计分 |
| 280 s | +20 | **+40.00** | 按公式计分 |
| 300 s | 0 | **0.00** | 恰好达标 |
| 360 s | −60 | **0.00** | 慢于基准，时间分保底 0 |
| 600 s（时限届满） | −300 | **0.00** | 保底 0，另按未完成结算 |

> **参数可调**：若希望时间分权重更高，可将 `k` 调到 3（此时约 200 s 即封顶）；若希望更弱，取 1。`T₀` 与 `k` 一经赛前公布不得中途修改。

### 3.4 与原有排名规则的关系

- 正式成绩已含时间附加分，仍按正式成绩从高到低排名
- 正式成绩完全相同时，**任务用时较少者**排名靠前（沿用正式版）
- 时间附加分不参与"直接归零"判定，归零局面下成绩恒为 0

## 4. 普通安全扣分

| 违规类型 | 判定条件 | 扣分 |
|---|---|---|
| 超速 | 速度持续 > 20.5 km/h 达 0.5 s | −50（本局 1 次） |
| **限速区超速** | 车辆中心在 15 km/h 区间内，速度持续 > 15.5 km/h 达 0.5 s | 每车每区 −50，最多一次 |
| 急加速 / 急减速 | 加速度绝对值持续 > 5.0 m/s² 达 0.5 s | −50（本局 1 次） |
| 车辆或障碍物碰撞 | 与其他车辆或可判定碰撞的障碍物发生新接触 | 每次 −100，本局无次数上限 |
| 道路边界压线 | 评分轮廓接触主任务道路两侧黄色外边实线并持续 0.2 s | 每次 −50，本局无次数上限 |

补充口径：

- 压线范围仅限**黄色外边实线**；白色标线、路口开口、中央虚线、停止线、车位标线不计
- 单独接触外围保护空气墙不计碰撞
- 与同一障碍物持续接触只记一次，完全分开后再碰重新计次。两辆参赛车之间同一次接触合计一次。锥桶、水马、防撞桶等按碰撞计，位移无独立扣分。
- 持续压线记一次，离开黄色外边实线后重新接触可再计次。
- 限速区超速与全场超速**不重复计分**：同一次持续超速若同时越过两条阈值，只扣 −50
- 每个限速区覆盖对应直道的双向车道，判分路段见 §1.6。

## 6. 时限与结算

| 情况 | 结算规则 |
|---|---|
| 任务时限 | 600 s，从评分会话开始且场景就绪后计时 |
| 全部完成 | 九项成果齐备且未触发归零 → 立即结束并结算（含时间附加分） |
| 未全部完成 | 600 s 届满按未完成结算；已完成项保留得分，扣除已发生的安全扣分，时间分记 0（慢于基准不加分） |
| 直接归零 | 立即结束，正式成绩 = 0 |
| 系统异常 | 记为无效，不发布成绩，不按 0 分处理 |
| Python 退出 / 断线 | 不暂停计时；控制超时后车辆安全停车，未恢复则 600 s 后按未完成结算 |

## 7. 成绩计算示例

**示例 1（正常完成，有少量违规）**

- 完成：A/B/C 三个信号（240，其中 B 由信号车提交）+ 路障扫描（160）+ 两车通行（200）+ A、B 交付（400）+ 必经点（300）= **1300**
- 用时 226 s → `S_t = 2 × (300 − 226) = +148.00`
- 违规：超速 −50、压线（1 次）−50 = −100
- **正式成绩 = 1300 + 148 − 100 = 1348 分**

**示例 2（600 秒超时）**

- 完成：A/B/C（240）+ 扫描（160）+ 仅运输车 A 通行（100）+ 仅 A 泊位交付（200）+ 必经点（300）= **1000**
- 600 s 时限届满，时间分 **0.00**。
- 违规：碰撞 1 次 −100，限速区超速 1 次 −50。
- **正式成绩 = 1000 + 0.00 − 150 = 850 分**

**示例 3（穿越封闭区）**

- A/B/C（240）+ 扫码（160）+ 一辆运输车已通过环岛（100）= **500**。随后运输车进入封闭区，时间分 **0.00**。
- 触发"穿越封闭道路" → **正式成绩 = 0 分**

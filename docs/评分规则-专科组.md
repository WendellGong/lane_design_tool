# 港口迷雾协同运输场景 · 评分规则（专科组）

> **适用赛道**：`tracks/港口测试赛道-专科组.json`（123 个元素）
> **同场组别**：`本科组-基础版` / `本科组-进阶版` / `本科组-高级版`（见各自规则文件）
> **专科组三大差异**：① **整体难度降低**——取消全部 12 处施工窄口（断面恢复 7 m 双向通行）、取消 6 辆新增动态障碍（仅余场景原有 3 辆）、不设 15 km/h 限速区；② **必经点改为必过项**——未经过 `el_mwrj5xwvo1lrw` 直接判 **0 分**（不设「到达必经点」加分项）；③ **经过必经点后进入手动段**——弹屏提示「请手动操作」，车辆转人工驾驶完成剩余任务。
> **评分要点**：任务分 **1000**（四板块八项）｜时间附加分 **S_t = clamp(2 × (360 − T), 0, +200)**｜信号点对**运输车与信号车同时开放**

### 1.3 动态障碍物清单（本科组 6 辆，新增；专科组全部取消）

> **专科组差异**：下表 6 辆新增动态车**全部移除**（`dyn_cross_w`、`dyn_slalom_suv`、`dyn_rb_bike`、`dyn_h0_bike`、`dyn_h2_truck`、`dyn_h3_bike`），专科组全场仅余场景原有的 **3 辆**动态车（2 辆两轮车 + 1 辆 SUV，均在西侧与顶行低速巡航）。因此专科组不需要时空占用预测，按静态避障 + 常规跟车即可。


动态障碍物指**带直线运动预设**的车辆（`props.move = true`，沿车头方向以 `moveSpeed` 前进 `moveDistance` 米后停驻）。它们与静态窄口叠加，形成「通过时机窗口」—— 程序必须先预测动态车的位置与到达时间，再决定加速抢行、减速跟随还是停车等待。

**设计约束（已验证）**

- 所有轨迹终点均落在**非窄口路段**，不存在永久堵死
- 车辆本体与前进轨迹与既有车辆、信号灯、障碍物、路口的包围盒**零相交**
- 动态车限速不超过 20 km/h，与场景限速一致，不与"超速"判定冲突

**算法要求的变化**

| 能力 | v4（纯静态） | v5（含动态） |
|---|---|---|
| 障碍物表示 | 静态栅格 / ESDF | 需**时空占用预测**（按 moveSpeed × 剩余距离推算） |
| 决策 | 避障 → 通过 | **通行权博弈**：抢行 / 跟随 / 等待的代价比较 |
| 重规划触发 | 静态阻塞时 | 动态目标进入本车走廊且 TTC 低于阈值时 |
| 窄口处理 | 几何收窄 | 几何收窄 + **时间窗对齐**（等动态车让开再进） |

### 1.4 强制绕行：y = 1000 东段封闭

- 封闭区间：`x ∈ [2980, 3820]`，整幅封闭，动态路障即设于 `(3500, 1000)`
- 检测边界：以路障中心线两侧各 **7 m** 为界（13.9 m 宽，覆盖整幅 7 m 路宽）
- 绕行通路（任选其一，均为已建成道路）：
  - `临港南北向道路`：`(2800,1000) → (2800,1960) → (4000,1960) → (4000,1000)`，单程增加约 **260 m**
  - 反向亦可，但需与中横路的 S 弯、中央路口窄口叠加
- 该封闭为**静态封闭**（不依赖扫描结果）：即使尚未完成路障扫描，车辆也不得进入封闭区

| S 弯 | 无 | **无**（两折防撞桶已拆除） | — |

### 1.6 限速区（专科组不设）

专科组**不设 15 km/h 限速区**，赛道内也不含 6 处 15 km/h 限速牌，全场统一 20 km/h 上限，仅保留 v6 遗留的 3 块 20 km/h 进口提示牌。安全扣分中**没有「限速区超速」项**。

### 1.7 必经点与手动段（专科组核心机制）

**必经点**：`el_mwrj5xwvo1lrw`，坐标 `(4000, 1000)`，位于临港南北向道路与 y=1000 行东端的丁字路口中心，正好是 y=1000 东段封闭区（`x ∈ [2980, 3820]`）的**外侧绕行转角**。

赛道文件已在该元素写入如下 `props`，程序按此驱动 UI 与状态切换：

```json
{
  "checkpoint": "mandatory",
  "manual_drive": true,
  "hint": "请手动操作",
  "hint_delay": 3,
  "hint_duration": 5
}
```

| 字段 | 含义 |
|---|---|
| `checkpoint: mandatory` | 必过项标记，未触发即判 0 分 |
| `manual_drive: true` | 触发后车辆切换为手动驾驶 |
| `hint: "请手动操作"` | 弹屏文案 |
| `hint_delay: 3` | 触发后 3 s 弹屏（留给车辆完成点通过动作） |
| `hint_duration: 5` | 提示停留 5 s |

**判定与流程**

1. 任一车辆（运输车或信号车）中心进入必经点 **3 m** 范围并保持 **0.5 s** → 判定为「已经过」，每局只触发一次
2. 触发后 `hint_delay` 秒，屏幕弹窗显示 **「请手动操作」**，持续 `hint_duration` 秒
3. 弹窗期间车辆转入手动驾驶，**其后的路障扫描、路口通行、泊位交付均由人工完成**
4. 手动段**不豁免**任何安全扣分（超速、急加减速、碰撞、压线、撞移照常判定），并计入 600 s 时限
5. 至 600 s 结束仍未触发必经点 → 正式成绩 = 0

> 设计意图：必经点强制车辆走通封路绕行（不绕行到不了该点），并在绕行完成后把控制权交还给人，考察「自动段 + 手动段」的交接可靠性。手动段起点固定、终点由任务进度决定，各队可在同一位置对比手动驾驶水平。

## 2. 任务分：四板块八项（1000 分）

专科组**不设「到达必经点」加分项**——必经点改为必过门槛（未经过即 0 分，见 §5），因此任务分回到 1000 分的四板块八项结构。

### 2.1 板块构成

| 任务板块 | 计分项数 | 单项分值 | 板块满分 | 板块关系 |
|---|---|---|---|---|
| 现场信号确认 | 3 项 | 80 | 240 | 按 A → B → C 顺序确认；运输车 / 信号车均可提交 |
| 封闭道路扫描 | 1 项 | 160 | 160 | 三个信号全部确认后开放 |
| 中央路口依次通行 | 2 项 | 100 | 200 | 扫描完成后可申请；两车分别计分 |
| 指定车位停靠 | 2 项 | 200 | 400 | A、B 两泊位分别计分 |
| **合计** | **8 项** | — | **1000** | 完成一项得一项 |
| *（必经点 `el_mwrj5xwvo1lrw`）* | *必过项* | *不计分* | *—* | *未经过即 0 分；经过后弹屏「请手动操作」并转手动段* |

### 2.2 计分项完成条件

| 板块 | 得分项 | 完成条件 | 得分 |
|---|---|---|---|
| 现场信号 | A 号信号 | 任一车辆（运输车或信号车）提交正确验证码并通过确认 | 80 |
| 现场信号 | B 号信号 | A 完成后，任一车辆（运输车或信号车）提交正确验证码 | 80 |
| 现场信号 | C 号信号 | B 完成后，任一车辆（运输车或信号车）提交正确验证码 | 80 |
| 封闭道路扫描 | 动态路障 | 三信号齐备后，**信号车**进入路障 10 m 范围完成扫描 | 160 |
| 中央路口通行 | 运输车 A | 扫描完成后从规定入口申请获准，**整车驶出 6 m 互斥区**并到达对侧出口车道，成功释放通行权 | 100 |
| 中央路口通行 | 运输车 B | 同上（西进东出 / 东进西出，原路退回不计） | 100 |
| 车位停靠 | A 泊位交付 | A 泊位精确位置公开；已完成路口通行且未交付其它泊位的运输车进入泊位中心 **3 m** 范围，停稳并提交 | 200 |
| 车位停靠 | B 泊位交付 | 同上，两泊位须由不同运输车完成 | 200 |
> **必经点不是计分项，而是必过门槛**（机制详见 §1.7）：任一车辆中心进入 3 m 范围并保持 0.5 s 即视为经过，随后弹屏「请手动操作」并转手动段；至 600 s 仍未经过 → 正式成绩 = 0。该点位于 `(4000, 1000)`，为场景既有元素（`obstacle / beacon`），**不参与碰撞判定**，仅作判定标靶。

### 2.3 定位精度与观测

泊位精确位置取决于**信号确认数量 + 有效观测**：

- 信号未齐备时，观测只能提升到有界精度，交付窗口受限
- 三个信号齐备后，具备**两辆不同车辆**在有效时间窗内提交的合格观测，即可直接达到精确等级（不要求逐级重提）
- 共享定位本身不单独计分，仅影响泊位可交付性与路径规划精度
- **信标验证码（A / B / C）对运输车与信号车同时开放**：任一车辆驶入信号点感应范围并提交正确验证码即计分，不要求三个信号由同一辆车完成（例如运输车提交 A、信号车提交 B、C 同样有效）
- 动态路障扫描**仅限信号车**；中央路口通行与泊位交付**仅限运输车**
- 必经点**不限车型**，运输车或信号车触发均有效，但每局只触发一次；触发后进入手动段（§1.7）

## 3. 时间附加分（v3 改版）

### 3.1 基准时间 T₀ = 360 s

专科组直接指定 **T₀ = 360 s**＝本科组基准 300 s + **手动段 60 s**：专科组取消了全部窄口与 6 辆新增动态车，自动段实际更快，但经过必经点后要人工驾驶完成剩余任务，需为其预留时间。40 km/h 的理论用时（63.6 s）仅作"物理下界"参考，不是可达目标。

参考里程（沿路网中心线的最短路径，`tools/route_length.py` 可复算）：

| 线路 | 里程 |
|---|---|
| 信号车：起点 → A 号信号 | 287.3 m |
| 信号车：A → B 号信号 | 73.3 m |
| 信号车：B → C 号信号 | 80.0 m |
| 信号车：C → 动态路障（含封路绕行） | 265.7 m |
| **信号车线路合计** | **706.3 m** |
| 运输车 A：起点 → 中央路口 | 214.0 m |
| 运输车 A：中央路口 → A 泊位 | 224.7 m |
| **运输车 A 线路合计** | **438.7 m** |
| 运输车 B：起点 → 中央路口 | 367.3 m |
| 运输车 B：中央路口 → B 泊位 | 304.7 m |
| **运输车 B 线路合计** | **672.0 m** |

三车并行执行，本局用时由最长线路（信号车 706.3 m）决定。按 T₀ = 360 s 折算：

```
L_max = 706.3 m                                    （信号车线路最长）
v_avg = L_max / T₀ = 706.3 / 360 = 1.96 m/s ≈ 7.1 km/h
```

`T_op`（作业与等待）参考构成，沿用 v2 口径，仅作校核：

| 作业环节 | 时间 |
|---|---|
| 3 次信号读取与验证码提交 | 3 × 8 = 24 s |
| 动态路障扫描（驶近 10 m + 扫码） | 10 s |
| 2 次泊位停稳与交付确认 | 2 × 10 = 20 s |
| 中央路口互斥等待（两车依次通行） | 21 s |
| **合计** | **75 s** |

校验：**全程平均 7.1 km/h 即可拿满时间分**——远低于全场 20 km/h 上限。专科组无窄口、仅 3 辆动态车，自动段本可跑得更快，因此 360 s 的基准主要是在为**手动段**留余量（另含 75 s 作业与 60 s 手动交接/操作）；`600 s` 时限相对 360 s 基准仍有 1.7 倍余量。

### 3.2 计分公式

```
ΔT  = T₀ − T_actual            （单位：秒；正值 = 快于基准）
S_t = clamp( 2 × ΔT , 0 , +200 )
```

| 参数 | 取值 | 含义 |
|---|---|---|
| `T₀` | **360 s** | 基准时间（300 s 自动段 + 60 s 手动段） |
| `k` | **2 分 / 秒** | 每比基准快 1 秒加 2 分 |
| `S_max` | **+200 分** | 加分封顶（占任务分 1000 的 20%） |
| 下限 | **0 分** | 慢于 360 s 不加分，也不扣分 |

即：**实际用时每比基准少 1 秒加 2 分；慢于基准的秒数不计分（记 0），不产生负分。** 时间分只奖不罚，最大影响 +200 分。

### 3.3 算例

| 完成用时 T | ΔT = 360 − T | S_t | 说明 |
|---|---|---|---|
| 240 s | +120 | **+200（封顶）** | 等效 10.6 km/h，自动段极限 + 手动段顺畅 |
| 260 s | +100 | **+200（封顶）** | 等效 9.8 km/h |
| 300 s | +60 | **+120** | 等效 8.5 km/h，优秀 |
| 340 s | +20 | **+40** | 接近基准 |
| 360 s | 0 | **0** | 恰好达标 |
| 420 s | −60 | **0** | 慢于基准，时间分保底 0 |
| 600 s（时限届满） | −240 | **0** | 保底 0，另按未完成结算 |

> **参数可调**：若希望时间分权重更高，可将 `k` 调到 3（此时约 293 s 即封顶）；若希望更弱，取 1。`T₀` 与 `k` 一经赛前公布不得中途修改。

### 3.4 与原有排名规则的关系

- 正式成绩已含时间附加分，仍按正式成绩从高到低排名
- 正式成绩完全相同时，**任务用时较少者**排名靠前（沿用正式版）
- 时间附加分不参与"直接归零"判定，归零局面下成绩恒为 0

## 4. 普通安全扣分（每类只扣一次）

| 违规类型 | 判定条件 | 扣分 |
|---|---|---|
| 超速 | 速度持续 > 20.5 km/h 达 0.5 s（**手动段同样适用**） | −50（本局 1 次） |
| 急加速 / 急减速 | 加速度绝对值持续 > 5.0 m/s² 达 0.5 s | −50（本局 1 次） |
| 车辆或障碍物碰撞 | 与其它车辆或**正式可碰撞障碍物**（含 v4 新增的锥桶、水马、防撞桶、护栏、围挡）发生物理碰撞 | −100（本局 1 次） |
| 道路边界压线 | 评分轮廓接触主任务道路两侧黄色外边实线并持续 0.2 s | 每车 −50（每车 1 次） |
| **施工设施撞移（新增）** | 锥桶 / 水马 / 防撞桶被撞离原位 > 0.5 m，但车辆未受阻、未触发碰撞判定 | **每次 −50，本局最多 2 次** |

补充口径：

- 压线范围仅限**黄色外边实线**；白色标线、路口开口、中央虚线、停止线、车位标线不计
- 单独接触外围保护空气墙不计碰撞
- 施工设施撞移与碰撞**不重复计分**：若同时满足碰撞判定，只扣 −100
- 手动段（经过必经点后）**不豁免**任何扣分项，撞击封路构件同样按「施工设施撞移 / 碰撞」处理

## 5. 直接归零（优先于一切计分）

| 严重违规 | 触发条件 |
|---|---|
| **未经过必经点（专科组）** | 结算时全队任一车辆均未进入 `el_mwrj5xwvo1lrw` 的 3 m 范围 → **正式成绩 = 0**（无论任务分多少） |
| 穿越封闭道路 | 任一运输车进入 y=1000 东段封闭区 `x ∈ [2980, 3820]`（以路障中心线两侧各 7 m 为检测边界） |
| 未授权进入路口 | 任一运输车未取得通行权，进入中央路口中心 6 m 互斥控制区 |
| 持续严重越界 | 任一车辆中心超出场景地图边界 > 1.0 m，且连续保持 ≥ 1.0 s |

v4 补充：**撞倒围挡后继续通行**视为"穿越封闭道路"，同样归零（不得以物理推开设施的方式通过封闭区）。

## 6. 时限与结算

| 情况 | 结算规则 |
|---|---|
| 任务时限 | 600 s，从评分会话开始且场景就绪后计时 |
| 全部完成 | 八项成果齐备、**必经点已过**且未触发归零 → 立即结束并结算（含时间附加分） |
| 未全部完成 | 600 s 届满按未完成结算；已完成项保留得分，扣除已发生的安全扣分，时间分记 0（慢于基准不加分）；**必经点未过则成绩直接为 0** |
| 直接归零 | 立即结束，正式成绩 = 0 |
| 系统异常 | 记为无效，不发布成绩，不按 0 分处理 |
| Python 退出 / 断线 | 不暂停计时；控制超时后车辆安全停车，未恢复则 600 s 后按未完成结算 |

## 7. 成绩计算示例

**示例 1（正常完成，手动段顺利）**

- 完成：A/B/C 三个信号（240）+ 路障扫描（160）+ 两车通行（200）+ A、B 交付（400）= **1000**
- 必经点已过，手动段无失误
- 用时 300 s → `S_t = 2 × (360 − 300) = +120`
- 违规：超速 −50、压线（1 车）−50 = −100
- **正式成绩 = 1000 + 120 − 100 = 1020 分**

**示例 2（手动段失误 + 未完成一项）**

- 完成：A/B/C（240）+ 扫描（160）+ 仅运输车 A 通行（100）+ 仅 A 泊位交付（200）= **700**
- 必经点已过，手动段撞封路构件 1 次
- 用时 420 s → 慢于基准 360 s，`S_t = 0`
- 违规：施工设施撞移 1 次 −50
- **正式成绩 = 700 + 0 − 50 = 650 分**

**示例 3（两车都没走到必经点）**

- 任务分 520，用时 150 s，`S_t = +200（封顶）`
- 结算时全队均未进入必经点 3 m 范围 → **正式成绩 = 0 分**（时间分不挽回）

# 厂仓物流协同运输场景 · 评分规则（专科组）

## 赛题目标与车辆功能

### 赛题目标

在厂仓物流（厂区仓库物流）协同运输场景中，由程序自动控制多车协同完成物资交付。按 A → B → C 顺序确认信号，任一参赛车可在封闭区东口外扫码，运输车随后通过受控环岛并交付。同一辆运输车依次完成 A、B 泊位交付。

### 车辆功能

任务车辆共 **2 辆**：**1 辆运输车**（卡车）与 **1 辆信号车**（轿车）。

| 车辆 | 数量 / 车型 | 功能与权限 |
|---|---|---|
| **运输车** | 1 辆 / 卡车 | 可确认信号、扫码、触发必经点、申请通过受控环岛，并在指定车位停稳交付。同车先 A 后 B |
| **信号车** | 1 辆 / 轿车 | 可确认信号、在三个信号齐备后到东口扫码、触发必经点；环岛任务通行和泊位交付由运输车完成 |

权限要点：

- **验证码（A / B / C）**：对运输车与信号车**同时开放**，任一车辆驶入7 m 范围并调用 `submit_key` 提交正确验证码即计分，不要求同一辆车完成全部信号。
- **目标观测**：A 确认后公布停车坪 1，B 确认后公布停车坪 2，C 确认后公布两个编号车位和东口扫码点。
- **必经点**：不限车型，运输车或信号车中心进入 3 m 范围并保持 0.5 s 即触发（本科组为计分项，专科组为必过门槛）。
- **其他交通参与者**：SUV、巴士、两轮车与行人仅作场景布景或动态障碍，不承担赛题任务。

### 1.7 必经点（专科组核心机制）

**必经点**：`el_mwrj5xwvo1lrw`，坐标 `(4000, 1000)`，位于临港南北向道路与 y=1000 行东端的丁字路口中心，正好是 y=1000 东段封闭区（`x ∈ [2980, 3820]`）的**外侧绕行转角**。

| 字段 | 含义 |
|---|---|
| `checkpoint: mandatory` | 必过项标记，未触发即判 0 分 |

## 2. 任务分：四板块七项（900 分）

专科组**不设「到达必经点」加分项**——必经点改为必过门槛（未经过即 0 分，见 §5）；同时全场仅 1 辆运输车，中央路口通行合并为 1 项、两泊位由同一车依次交付，因此任务分为 900 分的四板块七项结构。

### 2.1 板块构成

| 任务板块 | 计分项数 | 单项分值 | 板块满分 | 板块关系 |
|---|---|---|---|---|
| 现场信号确认 | 3 项 | 80 | 240 | 按 A → B → C 顺序确认；运输车 / 信号车均可提交 |
| 封闭道路扫描 | 1 项 | 160 | 160 | 三个信号全部确认后开放 |
| 中央路口通行 | 1 项 | 100 | 100 | 扫描完成后可申请；仅 1 辆运输车通过 |
| 指定车位停靠 | 2 项 | 200 | 400 | A、B 两泊位分别计分，由同一运输车依次交付 |
| **合计** | **7 项** | — | **900** | 完成一项得一项 |
| *（必经点 `el_mwrj5xwvo1lrw`）* | *必过项* | *不计分* | *—* | *未经过即 0 分* |

### 2.2 计分项完成条件

| 板块 | 得分项 | 完成条件 | 得分 |
|---|---|---|---|
| 现场信号 | A 号信号 | 任一车辆（运输车或信号车）提交正确验证码并通过确认，公布停车坪 1 | 80 |
| 现场信号 | B 号信号 | A 完成后，任一车辆（运输车或信号车）提交正确验证码，公布停车坪 2 | 80 |
| 现场信号 | C 号信号 | B 完成后，任一车辆（运输车或信号车）提交正确验证码，公布两个编号车位和扫码点 | 80 |
| 封闭道路扫描 | 东口扫码点 | 三信号齐备后，任一参赛车中心距 `roadblock_scan_point` 平面距离 **10 m 以内（含 10 m）**，调用 `scan`，首次成功公布封闭范围 | 160 |
| 中央路口通行 | 唯一运输车 | 扫码后在环岛东或西入向车道调用 `request_entry`。获准后通过环道，从对侧出向车道驶出。车尾清出环道后调用 `release` | 100 |
| 车位停靠 | A 泊位交付 | 完成环岛通行的运输车将车中心停入停车坪 1 的 1 号位（2.5 m × 5.3 m），车速 ≤ 0.25 m/s 持续至少 1.2 秒，调用 `deliver` | 200 |
| 车位停靠 | B 泊位交付 | 同上，停车坪 2 的 2 号位。同一运输车先 A 后 B | 200 |

> **加分项（时间附加分）**：全部任务完成时，用时每比基准 **360 s** 少 **1 秒**加 **2 分**，封顶 **+200 分**。按两位小数结算，见 §3。

> **必经点不是计分项，而是必过门槛**（机制详见 §1.7）：任一车辆中心进入 3 m 范围并保持 0.5 s 即视为经过；至 600 s 仍未经过 → 正式成绩 = 0。该点位于 `(4000, 1000)`，为场景既有元素（`obstacle / beacon`），**不参与碰撞判定**，仅作判定标靶。

### 2.3 定位精度与观测

泊位信息由信号确认进度逐步公开：

- A 确认后公布停车坪 1 的中心位置，B 确认后公布停车坪 2 的中心位置。
- C 确认后公布两个编号车位的具体位置和扫码点。
- 共享信息随任务状态更新，无需另行提交目标观测。
- **信标验证码（A / B / C）对运输车与信号车同时开放**：任一车辆驶入信号点7 m 范围并调用 `submit_key` 提交正确验证码即计分，不要求三个信号由同一辆车完成（例如运输车提交 A、信号车提交 B、C 同样有效）
- 信号车或运输车均可扫码。正式环岛通行和泊位交付仅限运输车。
- 必经点**不限车型**，运输车或信号车触发均有效，但每局只触发一次

## 3. 时间附加分（v3 改版）

### 3.1 基准时间 T₀ = 360 s

本版直接指定 **T₀ = 360 s**。

参考线路（路网里程随实际选路变化）：

| 线路 | 里程 |
|---|---|
| 信号车：起点 → A 号信号 | 按实际选路 |
| 信号车：A → B 号信号 | 按实际选路 |
| 信号车：B → C 号信号 | 按实际选路 |
| 信号车：C → 东口扫码点（含封路绕行） | 按实际选路 |
| **信号车线路合计** | 按实际路线合计 |
| 运输车：起点 → 受控环岛 | 按实际选路 |
| 运输车：受控环岛 → A 泊位 | 按实际选路 |
| 运输车：A 泊位 → B 泊位（同车依次交付） | 按实际选路 |
| **运输车线路合计** | 按实际路线合计 |

任务可由多车并行完成，实际用时取决于各车路线、等待和作业。

`T_op`（作业与等待）参考构成，沿用 v2 口径，仅作校核：

| 作业环节 | 时间 |
|---|---|
| 3 次信号读取与验证码提交 | 3 × 8 = 24 s |
| 东口扫码点扫描（驶近 10 m + 扫码） | 10 s |
| 2 次泊位停稳与交付确认（同一车） | 2 × 10 = 20 s |
| 中央路口通行等待 | 10 s |
| **合计** | **64 s** |

**260 s 及以内**完成全部任务可拿满时间分。达到 **360 s** 时，时间附加分为 0。

### 3.2 计分公式

```
ΔT  = T₀ − T_actual            （单位：秒；正值 = 快于基准）
S_t = round(clamp(2 × ΔT, 0, +200), 2)
```

| 参数 | 取值 | 含义 |
|---|---|---|
| `T₀` | **360 s** | 基准时间（直接指定） |
| `k` | **2 分 / 秒** | 每比基准快 1 秒加 2 分 |
| `S_max` | **+200 分** | 加分封顶（占任务分 900 的 22%） |
| 下限 | **0 分** | 慢于 360 s 不加分，也不扣分 |

仅在全部任务完成且未触发归零时计算，并四舍五入保留两位小数。**实际用时每比基准少 1 秒加 2 分；慢于基准的秒数不计分（记 0），不产生负分。** 时间分只奖不罚，最大影响 +200 分。

### 3.3 算例

| 完成用时 T | ΔT = 360 − T | S_t | 说明 |
|---|---|---|---|
| 240 s | +120 | **+200.00（封顶）** | 时间分封顶 |
| 260 s | +100 | **+200.00（封顶）** | 时间分封顶 |
| 300 s | +60 | **+120.00** | 按公式计分 |
| 340 s | +20 | **+40.00** | 接近基准 |
| 360 s | 0 | **0.00** | 恰好达标 |
| 420 s | −60 | **0.00** | 慢于基准，时间分保底 0 |
| 600 s（时限届满） | −240 | **0.00** | 保底 0，另按未完成结算 |

> **参数可调**：若希望时间分权重更高，可将 `k` 调到 3（此时约 293 s 即封顶）；若希望更弱，取 1。`T₀` 与 `k` 一经赛前公布不得中途修改。

### 3.4 与原有排名规则的关系

- 正式成绩已含时间附加分，仍按正式成绩从高到低排名
- 正式成绩完全相同时，**任务用时较少者**排名靠前（沿用正式版）
- 时间附加分不参与"直接归零"判定，归零局面下成绩恒为 0

## 4. 普通安全扣分

| 违规类型 | 判定条件 | 扣分 |
|---|---|---|
| 超速 | 速度持续 > 20.5 km/h 达 0.5 s | −50（本局 1 次） |
| 急加速 / 急减速 | 加速度绝对值持续 > 5.0 m/s² 达 0.5 s | −50（本局 1 次） |
| 车辆或障碍物碰撞 | 与其他车辆或可判定碰撞的障碍物发生新接触 | 每次 −100，本局无次数上限 |
| 道路边界压线 | 评分轮廓接触主任务道路两侧黄色外边实线并持续 0.2 s | 每次 −50，本局无次数上限 |

补充口径：

- 压线范围仅限**黄色外边实线**；白色标线、路口开口、中央虚线、停止线、车位标线不计
- 单独接触外围保护空气墙不计碰撞
- 与同一障碍物持续接触只记一次，完全分开后再碰重新计次。两辆参赛车之间同一次接触合计一次。锥桶、水马、防撞桶等按碰撞计，位移无独立扣分。
- 持续压线记一次，离开黄色外边实线后重新接触可再计次。

## 5. 直接归零（优先于一切计分）

| 严重违规 | 触发条件 |
|---|---|
| **未经过必经点（专科组）** | 结算时全队均未满足 §1.7 的必经点触发条件 → **正式成绩 = 0**（无论任务分多少） |
| 穿越封闭道路 | 任一运输车中心进入 y=1000 东段封闭区 `x ∈ [2980, 3820]`（道路中心线两侧各 7 m，扫码前后均判定） |
| 未授权进入路口 | 扫码后，任一运输车未取得通行权，车中心进入内半径 12 m、外半径 23.25 m 的受控环岛环道 |
| 持续严重越界 | 任一车辆中心超出场景地图边界 > 1.0 m，且连续保持 ≥ 1.0 s |

## 6. 时限与结算

| 情况 | 结算规则 |
|---|---|
| 任务时限 | 600 s，从评分会话开始且场景就绪后计时 |
| 全部完成 | 七项成果齐备、**必经点已过**且未触发归零 → 立即结束并结算（含时间附加分） |
| 未全部完成 | 600 s 届满按未完成结算；已完成项保留得分，扣除已发生的安全扣分，时间分记 0（慢于基准不加分）；**必经点未过则成绩直接为 0** |
| 直接归零 | 立即结束，正式成绩 = 0 |
| 系统异常 | 记为无效，不发布成绩，不按 0 分处理 |
| Python 退出 / 断线 | 不暂停计时；控制超时后车辆安全停车，未恢复则 600 s 后按未完成结算 |

## 7. 成绩计算示例

**示例 1（正常完成）**

- 完成：A/B/C 三个信号（240）+ 路障扫描（160）+ 单车通行（100）+ A、B 交付（400）= **900**
- 必经点已过。
- 用时 300 s → `S_t = 2 × (360 − 300) = +120.00`
- 违规：超速 −50、压线（1 次）−50 = −100
- **正式成绩 = 900 + 120 − 100 = 920 分**

**示例 2（600 秒超时，尚未交付）**

- 完成：A/B/C（240）+ 扫描（160）+ 通行（100）= **500**
- 必经点已过，两个泊位均未完成。
- 600 s 时限届满，时间分 **0.00**。
- 违规：发生一次碰撞，扣 100。
- **正式成绩 = 500 + 0.00 − 100 = 400 分**

**示例 3（全队未走到必经点）**

- A/B/C（240）+ 扫码（160）+ 单车通行（100）= **500**。600 s 结算，时间分 **0.00**。
- 结算时全队均未触发必经点 → **正式成绩 = 0 分**
